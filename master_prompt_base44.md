A) Master prompt для Base44

Сгенерируй мобильное приложение (Android/iOS) в Base44 для расчета себестоимости рецептов и маржинальности. Приложение должно устанавливаться как standalone (предпочтительно PWA или доступный вариант нативной сборки в Base44). Архитектура offline-first: все данные и расчеты локально на устройстве, без внешних API. Синхронизация — только опционально, по умолчанию local-only. Фото хранятся локально, с ограничением размера/сжатием. Без авторизации, без аналитики и трекеров.

Цели и результат:
- Показывать себестоимость рецепта и одной порции.
- При введенной цене продажи — прибыль и маржинальность в деньгах и процентах, опционально markup%.

Сущности/таблицы и поля:
1) Products (ингредиенты)
- id
- name
- unit_type (г/кг, мл/л, шт)
- purchase_price
- purchase_qty
- unit_price (расчетное)
- store_name
- store_link
- product_photo
- notes
- created_at
- is_archived

2) Recipes
- id
- name
- servings_or_output_qty
- output_unit
- recipe_photo (поддержка обновления в любое время; можно хранить как одно текущее фото + история по желанию)
- sale_price
- created_at

3) RecipeItems
- id
- recipe_id
- product_id
- used_qty
- used_unit
- cost_item (расчетное)

4) (опционально) Stores
- id
- name
- link

Логика расчетов (обязательно реализовать):
- unit_price = purchase_price / purchase_qty
- item_cost = unit_price * used_qty
- total_recipe_cost = Σ(item_cost)
- cost_per_unit = total_recipe_cost / servings_or_output_qty
- profit = sale_price - cost_per_unit
- margin_percent = profit / sale_price * 100
- markup_percent (опционально) = (sale_price - cost_per_unit) / cost_per_unit * 100

Обработка единиц:
- Поддержать г/кг, мл/л, шт.
- Если единицы в продукте и в рецепте различаются в одной группе (г↔кг, мл↔л), конвертировать автоматически.

Ключевые сценарии и экраны:
1) Продукты (CRUD)
- Добавление вручную: название, единица измерения, цена покупки, количество покупки, где куплено (текст), опционально ссылка, фото (галерея или камера), опционально дата покупки и заметки.
- Быстрый добавлятор: минимум полей (name, unit_type, purchase_price, purchase_qty) + раскрытие “Дополнительно”.
- Поиск и фильтр по названию и магазину.
- Архивация и удаление (удаление — подтверждение).

2) Рецепты (CRUD)
- Создание рецепта: название, список ингредиентов (выбор из продуктов), количество каждого ингредиента (used_qty + used_unit), количество порций/выход готового продукта (servings_or_output_qty + output_unit), фото готового продукта (галерея/камера).
- Важно: фото готового продукта можно добавлять/обновлять в любой момент (кнопка “Добавить/Обновить фото” на экране рецепта).

3) Экран рецепта (основной расчет)
- Таблица ингредиентов: название продукта, used_qty, used_unit, unit_price, cost_item.
- Итог: total_recipe_cost, cost_per_unit.
- Блок цены продажи: поле sale_price (per unit/per portion).
- Расчет и показ: profit, margin_percent, (опционально) markup_percent.
- Валидация: все цены и количества > 0; sale_price > 0 для расчета маржи; предупреждения если нет sale_price/servings.

4) Главный экран
- 2 большие кнопки: “Продукты” и “Рецепты”.
- Быстрый “+” для добавления.
- Карточки с фото как визуальные подсказки.

Отчеты (минимум 2):
- Самые дорогие ингредиенты (top by unit_price).
- Рецепты по марже (top/bottom по margin_percent или profit).

Экспорт/резервная копия:
- Экспорт данных (продукты, рецепты, recipe items, метаданные фото) в файл JSON/CSV.
- Импорт/restore из backup-файла.
- Если фото физически не включаются в backup — явно указать это в UI и предложить альтернативу (например, экспорт фото отдельным архивом).

Настройки:
- Символ валюты (пользовательский).
- Переключатель синхронизации (если поддерживается) — по умолчанию выключен.

UX/UI требования:
- Мобильный интерфейс с яркой “кондитерской” эстетикой, но строгой читаемостью цифр.
- Акцентные карточки с фото продукта/рецепта.
- Четко выделить: Себестоимость, Цена продажи, Прибыль, Маржа %.

Нефункциональные требования:
- Offline-first, все данные и расчеты локально.
- Никаких обязательных внешних сервисов.
- Без логина.

B) Чек-лист результата (10–15 пунктов)
1) Приложение устанавливается на устройство как standalone и работает без интернета.
2) Все данные сохраняются локально (продукты, рецепты, фото).
3) Можно создать продукт с фото из камеры или галереи.
4) Быстрый добавлятор продукта содержит только обязательные поля.
5) Поиск и фильтр продуктов работает по названию и магазину.
6) Рецепт позволяет выбрать ингредиенты из базы продуктов.
7) Для ингредиентов в рецепте корректно конвертируются г↔кг и мл↔л.
8) Себестоимость рецепта и порции рассчитывается по формулам.
9) При вводе цены продажи показываются прибыль и маржа %.
10) Есть предупреждения при отсутствии цены продажи или порций.
11) Фото готового продукта можно обновить в любое время.
12) Отчет “Самые дорогие ингредиенты” сортирует по unit_price.
13) Отчет “Рецепты по марже” показывает top/bottom.
14) Экспорт создает файл JSON/CSV, импорт восстанавливает данные.
15) UI использует яркую “вкусную” стилистику с хорошей читаемостью чисел.

C) 5 названий приложения + 5 идей визуального стиля
Названия:
1) KondiCalc
2) SweetMargin
3) COGS Patisserie
4) РецептПрофит
5) МаржаСладко

Идеи визуального стиля:
1) Пастельная палитра: кремовый фон, клубничный акцент, шоколадные заголовки; иконки-ингредиенты.
2) Контраст “ваниль + мята”: светлый фон, мятные кнопки, темно-серый текст, пиктограммы рецептов.
3) “Карамель и ягоды”: карамельные карточки, ягодные акценты, тонкие линии разделителей.
4) “Кондитерская витрина”: белый фон, золотистые акценты, карточки с легкой тенью.
5) “Сиреневый мусс”: нежный сиреневый градиент, розовые акценты, округлые карточки.
